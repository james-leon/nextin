# M4 — Parcours client web

Statut : **terminé, en attente de validation.**

Parcours : scan → choix du service → ticket → suivi en temps réel → appel → passage → note.
Les écrans suivent les maquettes 01 à 03 et leurs compositions dans `/design`.

## Ce qui est fait

### Pages client (`app/(client)`)
| Page | Rôle |
|---|---|
| `/` | Écran 01, toujours sombre : « Scannez pour commencer ». Le cadre de visée ouvre la caméra arrière. Le décodage est natif (`BarcodeDetector`) ; sinon `jsQR` est chargé à ce moment-là seulement. Un lien mène à la saisie du code. Barre d'onglets Scanner / Mon ticket / Profil. |
| `/c` | Saisie du code de l'établissement : les 6 caractères imprimés sous le QR code. |
| `/q/<jeton ou code>` | Écran 02 « Choisir un service ». Badge « QR code reconnu » ou « Code reconnu ». Chaque service affiche ses personnes en attente et l'attente estimée, **mises à jour en direct**. Le premier service est présélectionné. L'interrupteur « Accès prioritaire » n'apparaît que si l'agence et le service l'acceptent ; il demande alors un motif. L'agence fermée est signalée. Action principale « Prendre mon ticket » dans la BottomBar. |
| `/t/<jeton>` | Écran 03 « Mon ticket ». Le numéro et l'attente sont les héros. Barre de progression et ligne « En cours : C-043 · Guichet 2 ». Partage du lien. Annulation avec confirmation. |
| `/t` | Onglet « Mon ticket » : rouvre le ticket en cours de l'appareil, sinon invite à scanner. |
| `/profile` | Apparence (Auto / Clair / Sombre) et langue (FR / EN). Mention de confidentialité. Lien vers l'espace du personnel. |

### États de « Mon ticket »
- **En attente** : position et attente recalculées à chaque diffusion du tableau de l'agence.
- **Alerté** (« C'est votre tour · Présentez-vous · Cabinet 3 ») : la carte passe au vert. Le téléphone vibre et émet deux notes, et le titre de l'onglet change. Chaque rappel déclenche un nouveau signal et le badge « Rappel n° N ».
- **Admis** (« Vous êtes reçu ») : plus de bouton d'annulation.
- **Terminé** : « Merci de votre visite » et note de 1 à 5 avec commentaire facultatif, une seule fois.
- **Annulé ou absent** : message et « Prendre un nouveau ticket ».
- Après une coupure réseau, un badge « Connexion perdue » s'affiche. La page se reconnecte seule, y compris au retour de veille, et recharge l'état du ticket.

### Prise de ticket
- Une session anonyme Supabase est créée à la demande, avec le captcha natif si Turnstile est actif. Elle est gardée sur l'appareil et rafraîchie automatiquement.
- La demande part vers `POST /api/tickets` avec un nouveau jeton Turnstile.
- Si le client a déjà un ticket dans l'agence, il est renvoyé vers ce ticket.

### Performance (budget < 200 Ko, utilisable en 3G)
- Pas de supabase-js sur les pages client. On utilise à la place :
  - un client Realtime Broadcast minimal (`lib/client/realtime.ts`, protocole Phoenix, une connexion par page, reconnexion avec délais croissants) ;
  - des appels REST directs (`lib/client/supabase-public.ts`) ;
  - la session anonyme (`lib/client/anon-session.ts`).
- Pas de next-intl côté navigateur sur ces pages. Un traducteur minimal (`lib/i18n/lite.tsx`, `lib/i18n/format.ts`) gère les variables et les pluriels ICU ; il est testé sur les vrais messages.
- La confirmation d'annulation et la notation sont chargées seulement quand elles servent.
- Les helpers de file sans Zod sont regroupés dans `@nextin/shared/queue/live`.
- **Mesuré** (octets transférés au premier chargement, test Playwright) : `/` 174 Ko, `/q/…` 187 Ko, `/t/…` 187 Ko.

### Espace du personnel
- **Réglages** (`/app/settings`) : compte, Apparence (Auto / Clair / Sombre), Langue (FR / EN), déconnexion. Accessible depuis « Mes établissements » (bouton Réglages) et depuis le bas de la barre latérale du back-office. La déconnexion se fait désormais ici.
- **Poste de test temporaire**, réservé au personnel de l'agence, sous Agence → « Poste de test » (`…/branches/<agence>/test-desk`) :
  - choix du poste, ouverture et fermeture ;
  - « Alerter le suivant » ;
  - « Admettre », avec un chrono visible qui démarre à l'admission ;
  - « Terminer », « Rappeler », « Absent ».

  La page se met à jour en direct. Elle sera retirée au M5 et remplacée par le poste de l'agent.

## Tester avec votre téléphone (même Wi-Fi que le PC)
1. Docker Desktop ouvert, puis `pnpm db:start`, `pnpm db:reset` et `pnpm seed:demo:local`.
2. `pnpm dev:lan`.
   - Le script détecte l'adresse IP du PC, par exemple `192.168.1.20`, et démarre l'application sur `http://192.168.1.20:3000`.
   - Tout passe par cette adresse : `APP_URL`, donc les QR codes et les PDF, ainsi que Supabase local (`http://192.168.1.20:54321`).
   - Pour forcer une autre adresse : `pnpm dev:lan -- --host 192.168.1.20`.
3. Au premier lancement, Windows demande d'autoriser Node.js (et Docker) sur le **réseau privé** : acceptez. Le Wi-Fi doit être déclaré « Réseau privé » dans les paramètres Windows.
4. Sur le PC, ouvrez `http://192.168.1.20:3000/login` et connectez-vous avec `accueil@doualaclinic.demo` (mot de passe de démo). Puis allez dans DOUALA CLINIC → Agences → Akwa :
   - **QR code** : le QR affiché à l'écran pointe vers l'adresse du PC. Scannez-le avec l'**appareil photo du téléphone**.
   - **Poste de test** : choisissez un cabinet, ouvrez-le, puis « Alerter le suivant » et « Admettre ».
5. Sur le téléphone : choisissez un service, « Prendre mon ticket », et laissez la page ouverte. Elle se met à jour toute seule, vibre et sonne à votre tour, puis propose la note après « Terminer ».

Ce qui ne marche pas en Wi-Fi local, parce que l'adresse est en `http` et non en `https` :
- **le scanner intégré** : le navigateur refuse la caméra hors `https`. Le scan par l'appareil photo du téléphone et la saisie du code fonctionnent ;
- **le partage natif** : le bouton de partage bascule sur WhatsApp ;
- **l'installation PWA**.

Tout fonctionnera en production (`https`).
