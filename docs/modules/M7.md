# M7 — Notifications : WhatsApp, web push, SMS de secours

Statut : **terminé avec un faux fournisseur, en attente de validation**. Le compte Meta Business n'est pas encore prêt : tant que `WHATSAPP_TOKEN` et `WHATSAPP_PHONE_NUMBER_ID` sont vides, rien n'est envoyé. Le texte de chaque message est conservé et lisible avec `pnpm notify:outbox`.

## Ce qui est fait

### Côté patient (« Mon ticket »)
- **« Recevoir mes alertes sur WhatsApp »** (bouton teinté, sous la carte du ticket) :
  - le bouton ouvre WhatsApp avec le message prérempli `NEXTIN C-047 7K3Q` : numéro du ticket, 4 derniers caractères du lien personnel, et `EN` en anglais ;
  - **l'opt-in vient toujours du patient** ;
  - une fois le message envoyé, la page affiche en direct « Alertes WhatsApp activées » et indique qu'on peut fermer la page.
- **Notifications sur ce téléphone** (web push, en complément) :
  - le bouton n'apparaît que si le navigateur le permet : HTTPS, Android, ou iPhone avec l'app installée sur l'écran d'accueil ;
  - il faut aussi que les clés VAPID soient configurées.
- **Numéro saisi à l'accueil** (M5) : il faut l'accord du patient, et la confirmation part avec un modèle approuvé.

### Messages envoyés
Jamais de nom. Seuls figurent le numéro du ticket, l'établissement et l'agence, le poste, la position et l'attente.

| Événement | Déclencheur | Modèle Meta |
|---|---|---|
| Confirmation | opt-in du patient, numéro saisi à l'accueil | `ticket_confirme` |
| Bientôt votre tour | il reste au plus N personnes devant (`branch_settings.almost_turn_threshold`, 3 par défaut) ; une seule fois, et couvert par la confirmation si le ticket est déjà proche | `bientot_votre_tour` |
| C'est votre tour | « Alerter le suivant », puis chaque « Rappeler » | `cest_votre_tour` |
| Ticket reculé | « Reculer de 3 places » à l'accueil | `ticket_recule` |
| Praticien absent | réorientation vers un collègue (M5) | `praticien_reoriente` |
| Praticien en retard | retard déclaré, avec l'heure de retour | `praticien_en_retard` |

Règles d'envoi :
- **WhatsApp** :
  - dans les 24 h qui suivent le dernier message du patient (fenêtre WhatsApp), le texte part en message libre ;
  - en dehors de cette fenêtre, il part par **modèle approuvé**.
- **Pertinence** : un message devenu inutile au moment de l'envoi est ignoré, par exemple « bientôt votre tour » alors que le patient est déjà appelé.
- **Relances** : 3 tentatives au plus, à 30 s puis 2 min (limite de débit, réseau).
- **SMS de secours** :
  - envoyé tout de suite si WhatsApp échoue définitivement (numéro sans WhatsApp, statut `failed` reçu par webhook) ;
  - pour « c'est votre tour », envoyé aussi si WhatsApp n'a pas confirmé la remise dans les **2 minutes**.
- **STOP** (ou ARRÊT) : désinscription globale du numéro (haché en SHA-256), messages en attente annulés, réponse de confirmation. **START** réactive les messages.
- Un autre message du patient reçoit une aide, au plus une fois par jour.

### Architecture
- **Base** (`supabase/migrations/20261103090000_m7_notifications.sql`) :
  - `notification_contacts` est complétée par `wa_id`, l'abonnement push et la fenêtre de 24 h ;
  - nouvelles tables `notification_jobs` (file d'envoi, `dedupe_key` unique), `provider_webhook_events` (journal brut et idempotence) et `whatsapp_opt_outs` ;
  - les messages sont mis en file **par des déclencheurs SQL** : événements de ticket, retard d'un praticien, nouveau contact.
- **Expéditeur** (`POST /api/notifications/dispatch`, secret partagé) :
  - il réserve les messages dus (`FOR UPDATE SKIP LOCKED`, aucun double envoi), les envoie, puis enregistre le résultat ;
  - **réveil** : à chaque mise en file, la base appelle l'expéditeur avec pg_net (adresse et secret dans Supabase Vault). pg_cron reprend chaque minute les relances et les délais de garde ;
  - **en développement** (et pendant les tests), l'application lit la file elle-même toutes les 3 s : la base distante ne peut pas joindre votre PC.
- **Webhook WhatsApp** (`/api/whatsapp/webhook`) :
  - vérification de l'abonnement (GET) ;
  - signature `X-Hub-Signature-256` vérifiée à temps constant ;
  - chaque événement n'est traité qu'une fois ;
  - statuts de remise : un statut ne revient jamais en arrière.
- **Fournisseurs** (`lib/notifications/providers/`) :
  - WhatsApp Cloud API (Graph API `v23.0`) ou faux fournisseur ;
  - web push (VAPID) ou faux fournisseur ;
  - SMS `console`.
  - Avec le faux WhatsApp, un numéro se terminant par `99999` simule un échec définitif.
- **Textes** (`@nextin/shared/notifications`) : modèles FR/EN, SMS en alphabet GSM-7 (160 caractères), push, réponses aux messages entrants.
- **RLS** : file d'envoi, webhooks et STOP réservés au service role. Les numéros ne sont visibles que du personnel de l'agence (M5).
- **Purge** : contacts, textes envoyés et webhooks sont effacés après `data_retention_days`. Seuls restent l'événement, le canal, le statut et les horodatages (statistiques).

Parcours Playwright (`e2e/notifications.spec.ts`, faux fournisseurs imposés même si de vraies clés sont présentes) :
1. Lien WhatsApp prérempli. Webhook non signé ou mal signé refusé, vérification Meta acceptée.
2. Opt-in : la page passe en direct à « Alertes WhatsApp activées », confirmation en message libre, webhook rejoué sans effet.
3. « Bientôt votre tour », puis « c'est votre tour » avec SMS de garde programmé. L'accusé « delivered » met le statut à jour.
4. STOP : plus aucun message, même au rappel.
5. Numéro saisi à l'accueil : modèle `ticket_confirme`, échec simulé, **SMS de secours envoyé**.
6. Expéditeur protégé par son secret.

## Données de démo
Rien à ajouter. Un opt-in se fait sur un vrai ticket, ou en local avec `pnpm whatsapp:simulate`.

## Essayer en local sans compte Meta
1. Dans `apps/web/.env.local`, renseigner :
   - `WHATSAPP_APP_SECRET` : n'importe quelle chaîne en local ;
   - `NEXT_PUBLIC_WHATSAPP_NUMBER` : n'importe quel numéro, par exemple `237600000000`.
2. Lancer `pnpm dev` (ou `pnpm dev:lan --remote`) et prendre un ticket.
3. Simuler le message du patient : `pnpm whatsapp:simulate "NEXTIN C-001 AbC1"`. Le texte exact est sous le bouton de la page, dans le lien.
4. Lire les messages qui seraient partis : `pnpm notify:outbox`.
5. Simuler un STOP : `pnpm whatsapp:simulate STOP`. Simuler un accusé de remise : `pnpm whatsapp:simulate --status <id> delivered`.

## Ce que vous devez créer chez Meta (liste exacte)

### 1. Compte et application
1. **Meta Business Suite** (business.facebook.com) : un portefeuille d'entreprise au nom de Wintek. Faites la **vérification de l'entreprise** (Paramètres → Centre de sécurité) : sans elle, la limite reste de 250 conversations par jour.
2. **Meta for Developers** (developers.facebook.com) → Créer une app → type **Business** → ajouter le produit **WhatsApp**, rattaché au portefeuille Wintek.
3. **Numéro de téléphone** (WhatsApp → API Setup → Add phone number) :
   - un numéro **dédié**, jamais utilisé dans l'application WhatsApp (ou supprimé de celle-ci), capable de recevoir un SMS ou un appel de vérification ;
   - nom affiché : **NextIn** (approuvé par Meta) ;
   - catégorie : Services aux entreprises ;
   - photo : l'icône NextIn (tuile bleue à flèche blanche).
4. **Jeton permanent** : Paramètres de l'entreprise → Utilisateurs → **Utilisateurs système** → Ajouter (rôle Admin). Assignez-lui l'app et le compte WhatsApp (contrôle total), puis Générer un jeton avec les autorisations `whatsapp_business_messaging` et `whatsapp_business_management`, sans expiration. Le jeton temporaire de la page API Setup expire en 24 h : ne l'utilisez pas.
5. **Webhook** (WhatsApp → Configuration) :
   - URL de rappel : `<APP_URL>/api/whatsapp/webhook`, en HTTPS, donc l'adresse de production ;
   - jeton de vérification : la valeur de `WHATSAPP_VERIFY_TOKEN` ;
   - abonnez le champ **`messages`**, qui transmet les messages reçus et les statuts de remise.
6. Passez l'app en mode **Live** (App settings → Basic : URL de politique de confidentialité requise).

### 2. Variables d'environnement (Vercel et `apps/web/.env.local`)
| Variable | Où la trouver |
|---|---|
| `WHATSAPP_TOKEN` | jeton permanent de l'utilisateur système (étape 4) |
| `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp → API Setup → « Phone number ID » (pas le numéro lui-même) |
| `WHATSAPP_APP_SECRET` | App settings → Basic → **App secret** (Afficher) |
| `WHATSAPP_VERIFY_TOKEN` | chaîne aléatoire de votre choix, identique dans Meta (étape 5) |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | le numéro de l'étape 3 au format international sans « + », ex. `2376XXXXXXXX` |
| `NOTIFY_DISPATCH_SECRET` | chaîne aléatoire d'au moins 32 caractères (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | `npx web-push generate-vapid-keys` (indépendant de Meta, utilisable dès maintenant) |
| `VAPID_SUBJECT` | `mailto:` suivi d'une adresse de contact Wintek |

Ensuite :
- `pnpm db:push`, pour la migration M6 bis (derniers appels) et la migration M7 ;
- après le déploiement, **`pnpm notify:configure`**, une seule fois et à relancer si `APP_URL` ou `NOTIFY_DISPATCH_SECRET` change.

### 4. Vérifier, une fois tout en place
1. Prendre un ticket sur son téléphone, toucher « Recevoir mes alertes sur WhatsApp » et envoyer le message : la confirmation arrive en quelques secondes.
2. Depuis un poste, « Alerter le suivant » jusqu'à ce ticket : « C'est votre tour » arrive.
3. `pnpm notify:outbox` : les statuts passent de `sent` à `delivered` puis `read`.

## Reste à décider
- **Fournisseur SMS** : pour l'instant, faux fournisseur `console`, sans coût. Il faut choisir un fournisseur qui délivre bien au Cameroun (MTN et Orange), avec un nom d'expéditeur « NextIn » enregistré. Exemples : un agrégateur local, Orange SMS API Cameroun, Africa's Talking ou Twilio. L'ajouter ne demande qu'un fichier `lib/notifications/providers/sms.ts`.
